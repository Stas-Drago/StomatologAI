# План очистки и безопасной публикации DentalHelper

Этот документ фиксирует целевое состояние открытого репозитория и обязательный порядок его подготовки.

## Выполненные изменения

- Удален весь мессенджерский контур: исходный код, SQLite-хранилище, SDK и токен-ориентированная конфигурация.
- Поиск клиник перенесен в `web_api/clinic_search.py`; endpoint `GET /api/clinics?lat=&lon=` сохраняет выдачу максимум из семи клиник, отсортированных по фактическому расстоянию.
- Архитектура, README и зависимости больше не содержат упоминаний удаленного контура.
- Добавлена лицензия MIT и правила игнорирования локальных моделей, датасетов, сборочных артефактов, баз данных и виртуальных окружений.
- Эксперимент YOLO11n опубликован вместе с визуальными материалами обучения и валидации по подтверждению владельца об открытом происхождении данных. Решение по каждому артефакту приведено в `docs/training/yolov11n_caries/AUDIT.md`.

## Состав открытого репозитория

Публикуются исходный код сайта и API, конфигурации, документация, примеры окружения, метрики обучения и подтвержденные визуальные материалы эксперимента.

Не публикуются `.env`, ключи, токены, SQLite-файлы, `node_modules`, `web/dist`, `.venv`, модели и веса (`*.pt`, `*.onnx`), исходный датасет, логи, временные файлы и каталог `pet-project/`.

## Проверка перед первым коммитом

1. Создать новый пустой Git-репозиторий в корне и проверить правила: `git status --ignored`.
2. Найти секреты: `rg -n -i '(api[_-]?key|token|secret|password|ollama_api_key)' -g '!node_modules' -g '!web/dist' .`.
3. Проверить, что в staging не попали запрещенные артефакты: `git add -n .`, затем `git status --short`.
4. Найти крупные файлы: `find . -type f -size +50M -not -path './.git/*' -print`. Каждый файл должен быть исключен или иметь подтвержденную причину публикации.
5. Проверить, что отсутствуют удаленные модули, их SDK и переменные окружения; результат поиска по их прежним идентификаторам должен быть пустым.
6. Установить зависимости в чистое окружение и выполнить `./run_local.sh`; открыть `http://localhost:5173`, проверить загрузку фото и поиск клиник.
7. Проверить документацию обучения: в `docs/training/yolov11n_caries/` нет `.pt` и локальных путей к датасету; batch-материалы соответствуют подтвержденным открытым источникам.
8. Создать первый коммит только после успешного прохождения шагов 1-7; проверить `git show --stat --check HEAD`.
9. Создать публичный GitHub-репозиторий, добавить remote и выполнить `git push -u origin main`.
